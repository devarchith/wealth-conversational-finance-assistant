# Reconstruction Assumptions

1. The product title, abstract, finance-specific sprint documents, results chapter, and finance test cases outrank contradictory learning-platform prose.
2. The original repository and exact framework choices are unavailable; the selected Next.js/FastAPI/MongoDB stack is modern reconstruction, not historical fact.
3. The report demonstrates concepts and screenshots but does not provide a complete working schema, API, or source listing.
4. A modular monolith satisfies the documented boundaries with materially lower complexity than speculative microservices, queues, and serverless deployments.
5. Local email/password authentication is the required baseline. Social login/MFA are documented extension points because their evidence is limited.
6. “Transactions” means user activity/history unless a coherent, safe money-movement requirement exists; no actual money movement is implemented.
7. “Real-time financial data” is treated as a future integration. The reconstruction never fabricates live prices or performance rankings.
8. Personalized recommendations combine financial-profile data with deterministic, documented heuristics. AI does not calculate balances or guaranteed outcomes.
9. Provider credentials are deployment-owned environment variables. The unsafe report proposal to store user service passwords/keys is rejected.
10. Cloudinary uploads are limited to useful profile/supporting files; the application works with the mock provider.
11. The AI mode defaults to a deterministic mock provider so the full application and evaluation run without a paid API key.
12. MongoDB is the production persistence target; tests use an isolated repository implementation with identical ownership rules.
